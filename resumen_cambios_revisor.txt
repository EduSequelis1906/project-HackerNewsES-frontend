Resumen de cambios solicitados por el revisor

1. Paginacion de historias
- Stories muestra inicialmente 3 resultados.
- Se agrego el boton "Mostrar mas", que agrega otros 3 resultados por pulsacion.
- Al enviar una busqueda o limpiar el formulario, el contador vuelve a 3.
- El boton se estilizo con BEM como stories__more, respetando el diseno actual.

2. Manejo de errores de carga
- NewsCardList ya no se renderiza cuando existe un error de API.
- El usuario ve un unico mensaje de error, sin el mensaje de lista vacia debajo.

3. Navegacion del logo
- El enlace de marca en Header ahora usa Link de React Router.
- Navegar al inicio no recarga el documento ni reinicia la aplicacion.

4. Constantes centralizadas
- Se creo utils/constants.js.
- Se movieron API_BASE_URL, STORY_LIMIT y SAVED_STORIES_KEY.
- Tambien se centralizaron el tamano de pagina y los mensajes de carga,
  resultados de busqueda vacios y lista vacia.

5. Carga de API en App
- App ahora obtiene las historias y mantiene los estados de carga y error.
- Stories recibe estos valores por props y mantiene localmente la busqueda y
  la paginacion.
- La carga deja de depender del montaje de Stories, por lo que cambiar de ruta
  no inicia otra solicitud mientras App siga montado.

6. Validacion del formulario
- El campo de busqueda ahora incluye required.
- El boton Limpiar sigue permitiendo restablecer la lista completa.

7. Documentacion
- Se actualizo el README para reflejar que App carga las historias y que
  Stories controla la busqueda y la paginacion.

Validacion ejecutada
- npm run lint: correcto.
- npm run build: correcto.
